운영 관측성 구현 기록

실시간 대시보드를 백업하고 정적 문서로 전환한 운영 증거 정리

저자

배진후

1 전환 배경

기존 실시간 운영 대시보드는 Prometheus, Proxmox, Kubernetes, 배포 파이프라인 상태를 브라우저에서 직접 갱신하는 React/Vite 앱이었습니다. 공개 포트폴리오에서는 실행 중인 운영 UI보다 구현 의도와 검증 증거를 안정적으로 읽을 수 있는 문서가 더 적합하다고 판단해, 대시보드 앱은 백업하고 이 페이지를 정적 Quarto 문서로 교체했습니다.

항목 현재 처리
React/Vite 대시보드 archive/live-ops-dashboard/에 백업
공개 URL OpsDashboard.html 유지
공개 페이지 성격 실시간 UI가 아닌 운영 관측성 구현 기록
민감 정보 token, secret, 내부 credential 원문 미포함

2 관측 대상으로 삼은 상태

대시보드는 홈랩과 운영 클러스터를 “구축했다”는 설명을 넘어서, 어떤 상태를 읽고 어떤 기준으로 정상 여부를 판단했는지 보여주기 위한 도구였습니다.

관측 영역 확인하려던 상태 문서화 기준
Prometheus scrape target, workload metric, query 응답 target 수와 query 성공 여부
Proxmox node, VM inventory, 실행 상태 VM 상태와 운영 plane 연결
Kubernetes deployment, pod, ingress, storage Ready, Bound, Ingress host, rollout 상태
GitOps image tag, Argo CD sync, rollout commit SHA와 배포 상태 연결
Edge runtime public route, proxy, health endpoint 외부 접근 경로와 런타임 응답

3 아키텍처 관점

현재 공개 문서는 위 관계를 실시간으로 조회하지 않습니다. 대신 배포 기록, 스크린샷, 명령 실행 결과, 장애 대응 기록을 기준으로 운영 구조를 설명합니다.

4 구현 이력으로 남긴 의미

Read Model

운영 API는 클러스터와 가상화 계층의 상태를 읽기 전용으로 노출하는 경계였습니다.

Evidence

대시보드는 수동 캡처가 아니라 동일한 관측 지점을 반복해서 확인하기 위한 화면이었습니다.

Boundary

브라우저, 운영 API, Prometheus, Proxmox, Kubernetes 사이의 책임을 분리했습니다.

Archive

현재 공개 페이지에서는 앱을 제거하고, 과거 구현은 백업 디렉터리에 보존했습니다.

5 공개 문서에서 유지할 내용

  • 어떤 운영 상태를 관측 대상으로 삼았는지
  • GitOps 배포와 런타임 상태를 어떤 증거로 연결했는지
  • 장애 대응에서 어떤 원인과 조치를 분리했는지
  • 홈랩과 OKE production을 어떻게 역할 분리했는지
  • 민감 정보 없이 공개 가능한 운영 증거가 무엇인지

6 공개 문서에서 제거한 내용

  • 브라우저에서 직접 상태를 갱신하는 React UI
  • 실시간 상태 스트림과 주기적 API polling
  • 공개 사이트 산출물에 포함되던 대시보드 JavaScript bundle
  • Quarto dashboard format 전용 런타임 파일
  • 운영 API 도메인과 endpoint를 직접 여는 UI
