저자

배진후

1 문서 구성

이 문서는 mintcocoa-ops 저장소에서 확인한 운영 구조를 기준으로 정리했습니다. 홈랩 Kubernetes 실험을 그대로 production으로 부르는 대신, OKE production과 home k3s staging의 역할을 분리하고, GitOps 저장소가 어떤 desired state를 관리하는지 장별로 나눕니다.

문서 내용
1. OKE production GitOps 구조 mintcocoa-ops가 OKE production과 home k3s를 어떤 경계로 관리하는지 설명
2. home에서 OKE로 승격하는 배포 경계 base/overlay 구조와 수동 promotion workflow가 맡는 책임
3. docs.mintcocoa.dev 배포 경로 mintcocoa-docs가 개인 도메인에서 서빙되기까지의 CI와 GitOps 경로
4. 관측성과 운영 접근 경계 private ingress, IPSec operator path, observability stack의 공개/비공개 경계
5. Git 이력으로 확인한 운영 구조 변화 mintcocoa-ops 원격 로그에서 확인되는 production GitOps 전환 흐름
일치 없음

2 공개 범위

공개 문서에는 도메인, 저장소명, 앱 이름, 커밋 해시처럼 검증에 필요한 식별자는 남깁니다. 반면 Kubernetes API IP, private IP, OCID, token, Secret 값은 그대로 싣지 않고 역할과 경계만 설명합니다.

3 기준 근거

근거 확인한 내용
mintcocoa-ops OKE production GitOps, home k3s staging, Argo CD Application 구조
mintcocoa-docs workflow _site 렌더, GHCR 이미지, mintcocoa-ops OKE overlay image tag 갱신
apps/mintcocoa-docs/overlays/prod docs.mintcocoa.dev Ingress와 production image tag
apps/dropapp/overlays/prod drop.mintcocoa.dev Ingress, production resource/security patch

4 확인 명령

git -C /home/cocoa/mintcocoa-ops log --date=short --pretty=format:'%h %ad %s' --max-count=35
git -C /home/cocoa/mintcocoa-ops show HEAD:apps/mintcocoa-docs/overlays/prod/kustomization.yaml
git -C /home/cocoa/mintcocoa-ops show HEAD:apps/mintcocoa-docs/overlays/prod/ingress.yaml
