1.2 ServerCore에서 증명되는 내용

초기 ServerCore 문서는 “게임 서버 라이브러리”로 출발합니다. 핵심 근거는 다음입니다.

근거 내용
io_uring 직접 구현 이유 epoll의 read/write syscall 경로와 비교해 SQ/CQ 공유 메모리, Multishot Accept/Recv의 이점을 검증하려고 했습니다.
라이브러리 분리 이유 IoRing, Session, BufferPool 같은 코어와 GameRoom, PacketSession 같은 게임 프레임워크 계층이 섞인 문제를 분리했습니다.
주요 기술 Multishot Accept, Multishot Recv + Provided Buffer, MSG_RING, weak_ptr 기반 IoEvent owner, keep_alive 배치 보호, pending_io_ 기반 세션 수명관리
벤치마크 Echo 327K echo/s, 200봇 broadcast p50에서 epoll 대비 큰 지연 차이, Room sharding 효과

초기 벤치마크 보고서에는 Integrated, Separated, Epoll 세 모델 비교가 들어 있습니다. 즉 단순 구현 소개가 아니라 같은 게임 로직을 서로 다른 I/O 구조로 비교한 결과가 남아 있습니다.

1.3 FactionClash 클라이언트에서 증명되는 내용

초기 FactionClash 문서는 ServerCore 기반 GameServer와 연동되는 DirectX 11 클라이언트를 설명합니다.

근거 내용
기술 스택 C++, DirectX 11, Protobuf 3, Dear ImGui, WinSock2
네트워크 TcpClient, PacketFramer, PacketHandler, PacketBuilder, Binary Header + Protobuf payload
씬 구조 LoginScene, CharSelectScene, LobbyScene, GameScene
렌더링 InstanceRenderer, StructuredBuffer 인스턴싱, DrawIndexedInstanced, 프로시저럴 이펙트 셰이더
서버 연동 C_SCENE_READY, Room broadcast 준비 상태, MapData 기반 dungeon build, 서버 권위 판정

이 부분은 현재 저장소에서 삭제되었지만, 최초 커밋에는 03_FactionClash_Client/proto/battle.proto와 C++ 소스 파일이 함께 들어 있었으므로 “문서만 작성했다”보다 강한 증거로 볼 수 있습니다.

1.4 SwarmDominion에서 증명되는 내용

SwarmDominion은 구현 완료 프로젝트라기보다 DirectX 학습과 DX12/SVO 확장 설계 자료로 보는 것이 정확합니다.

근거 내용
DX11 구조 학습 WinMain, D3D11CreateDeviceAndSwapChain, RTV/DSV, ImGui DX11 backend, terrain/unit/particle layer
GPU 렌더링 개념 StructuredBuffer, ShaderResourceView, instanced draw, particle billboard
DX12/SVO 확장 설계 Sparse Voxel Octree, GPU voxelization, traversal shader, chunk dirty update, partial rebuild
레퍼런스 분석 SparseVoxelOctree, voxel-rs, unity-svo-demo, voxel-raycaster, Teardown, Atomontage, CryEngine SVOGI

따라서 이력상 SwarmDominion은 “그래픽스 구현 능력”보다는 “렌더링 파이프라인을 학습하고 DX12/SVO 구현 계획을 세운 자료”로 표현하는 것이 안전합니다.

1.5 무엇이 바뀌었는가

처음에는 세 프로젝트가 한 포트폴리오 저장소에 함께 있었습니다. 이후 저장소는 GitHub Pages 배포와 문서 공개에 맞춰 산출물 중심으로 정리되었고, 서버 런타임은 별도 구현 저장소와 연결되는 방향으로 재구성되었습니다.

이후 ServerCore 설명은 게임 서버 기능 자체보다 아래에 있는 네트워크 I/O 실행 기반으로 이동합니다. 현재 문서의 1장은 이 전환을 명시합니다.

처음에는 게임 서버를 만들기 위한 기반 코드로 시작했지만, TCP 연결 수락, 수신/송신, 시간 초과와 취소, 버퍼 소유권, 세션 수명주기, 스레드 간 작업 전달이 특정 게임 로직에만 종속되는 기능이 아니라고 정리했습니다.
