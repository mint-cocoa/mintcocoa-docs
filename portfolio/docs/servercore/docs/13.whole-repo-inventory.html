13. 전체 저장소 훑기 결과

13. 첫 커밋부터 현재까지 전체 저장소를 훑은 프로젝트/문서/운영 축 정리

1 전체 저장소 훑기 결과

이 장은 특정 주제 하나가 아니라 첫 커밋부터 현재까지의 저장소 전체를 훑었을 때 드러나는 작업 축을 정리합니다. 인프라 경험은 분명히 남아 있지만, 전체 이력은 서버 런타임, 클라이언트, 그래픽스, 문서화, 공개 사이트, 운영 대시보드, 출판 자동화가 함께 진행된 흐름입니다.

주의할 점은 portfolio-head 저장소 자체의 첫 커밋이 2026-04-09라는 것입니다. 2026년 이전 작업은 이 저장소의 Git history에는 없고, GitHub 계정의 다른 저장소와 일부 로컬 checkout에 남아 있습니다.

1.1 0. GitHub 계정 전체에서 보이는 범위

gh repo list mint-cocoa --limit 200로 확인한 계정 전체 스냅샷은 다음과 같습니다.

항목 값
전체 저장소 124개
fork가 아닌 저장소 106개
archived 저장소 44개
archive되지 않은 owner 저장소 64개
active owner 저장소의 주요 언어 C++ 19개, Python 15개, TypeScript 12개, JavaScript 6개, HCL 2개

이 숫자는 “모든 저장소가 동일한 수준의 포트폴리오 증거”라는 뜻이 아닙니다. fork 저장소와 archived 저장소는 관심사, 학습 경로, 실험 흔적을 보여주지만, 구현 역량의 핵심 증거는 owner 저장소와 현재 남아 있는 파일/커밋을 기준으로 봐야 합니다.

시기별로 묶으면 다음 흐름이 보입니다.

시기 대표 저장소 의미
2021-08 ~ 2023-12 CALCDDAY, opensource_android23-1, my-nextjs-app, blog-starter-kit, argocd-example-apps 웹, Android, Next.js, Kubernetes/GitOps 학습과 초기 프로젝트
2024-03 ~ 2024-12 ticket-project, user-api, mint-cocoa.github.io, nest-project-root, api-userendpoint, msa_final, terraform, baseball_analysis 웹/API/MSA, Python 백엔드, TypeScript 프론트엔드, IaC 실습
2025-02 ~ 2025-12 tcpechoserver, gameserver_example, new_gameserver, ruk_example, mmoserver, logameserver, newnew_server, youtube-backend, AI-cpp-debug C++ 서버/네트워크, 게임 서버 계열, 자동화 도구
2026-01 ~ 2026-03 new_servercore, servercore_v3, servercore, servercore_v4 ServerCore 계열을 여러 버전으로 실험한 흔적
2026-04 ~ 2026-06 libiouring-server, game-client, portfolio, iouring-runtime, home-k8s-gitops, ops-dashboard, mintcocoa-ops 서버 런타임, 클라이언트, 운영 대시보드, GitOps/IaC, 문서 출판을 하나의 포트폴리오 흐름으로 연결

1.2 0.1. 2026년 이전 이력은 별도 저장소에 있다

로컬 홈 디렉터리의 checkout과 GitHub 저장소 목록을 함께 보면 2026년 이전 이력은 다음처럼 확인됩니다.

저장소 remote 첫 커밋 의미
mint-cocoa.github.io https://github.com/mint-cocoa/mint-cocoa.github.io.git 2024-04-04 b1d993c Initial commit 개인 GitHub Pages 사이트 시작
msa_final https://github.com/mint-cocoa/msa_final.git 2024-10-14 a8c3085 feat: Initialize project structure... MSA 구조, API gateway, user/park/facility service, Docker/Kubernetes manifest
tcpechoserver / gameserver_example / new_gameserver https://github.com/mint-cocoa/* 2025년 생성 C++ 네트워크 서버와 게임 서버 계열 실험
NAIA2.0 / cocoa-naia https://github.com/DNT-LAB/NAIA2.0.git, https://github.com/mint-cocoa/NAIA2.0.git 2025-07-13 665783b Initial commit Mac OS 지원, external module system, WEBUI API 지원
ruk_example https://github.com/mint-cocoa/ruk_example.git 2025-07-29 6bf459e Initial commit 이후 서버 I/O 구조 분석과 IoWorker 구현으로 이어지는 런타임 계열 이력

PolyVGet-ffmpeg와 FreeRTOS처럼 더 오래된 커밋이 보이는 저장소도 있지만, 이는 upstream/vendor history 성격이 강해 개인 포트폴리오 증거로 바로 쓰기에는 부적절합니다.

따라서 포트폴리오에서 2026년 이전까지 포함하려면 portfolio-head의 Git log만 볼 것이 아니라 위 저장소들의 log와 GitHub repo 생성 이력을 함께 근거로 묶어야 합니다.

1.3 1. 초기에는 세 프로젝트가 같이 있었다

최초 커밋 85c8f49는 Initial commit: Game server portfolio documents라는 메시지를 갖지만, 실제 파일 목록은 ServerCore만이 아닙니다.

초기 경로 확인한 내용 해석
01_ServerCore_v4/ io_uring 기반 C++20 게임 서버 프레임워크, 벤치마크, 포트폴리오 문서 이후 서버 런타임 포트폴리오의 중심
02_SwarmDominion_DX11/ DX11 구조 학습, DX12/SVO 렌더러 설계, 레퍼런스 분석 그래픽스 학습과 확장 설계의 근거
03_FactionClash_Client/ DirectX 11 클라이언트 문서, C++ 소스, Protobuf 스키마 서버와 붙는 클라이언트 구조를 함께 다뤘다는 근거

이 초기 원본은 2026-04-14 13f2411에서 Pages 중심 저장소로 정리되며 삭제되었습니다. 그래서 현재 파일 트리만 보면 초기 클라이언트와 그래픽스 자료가 사라진 것처럼 보입니다.

1.4 2. 기술 문서를 제출 가능한 산출물로 바꿨다

2026-04-13 295be73은 단순 코드 커밋이 아니라 포트폴리오 산출물 정리 커밋입니다.

파일/작업 의미
01_ServerCore_v4/ServerCorePortfolio.pdf 서버 포트폴리오를 PDF 산출물로 생성
03_FactionClash_Client/ClientPortfolio.pdf 클라이언트 포트폴리오를 PDF 산출물로 생성
_pdf-defaults.yml PDF 출력 기본값 관리
html2pdf.py HTML 문서를 PDF로 변환하는 도구
한국어 자기소개/지원 문서 기술 설명을 지원 문서 형태로 다듬은 흔적

따라서 이 저장소는 구현 코드만이 아니라 “기술 내용을 읽히는 문서로 포장하고 제출 가능한 형태로 만드는 과정”도 보여줍니다.

1.5 3. 공개 사이트와 문서 형식을 계속 정리했다

2026-04-13 4469271부터 GitHub Pages 산출물이 추가되었고, 2026-04-26 6da88c6에서 문서 형식이 표준화되었습니다.

커밋 확인한 내용
4469271 rendered portfolio documents를 GitHub Pages 사이트로 추가
13f2411 Pages용 docs/만 남기도록 저장소 정리
6da88c6 _quarto.yml, docs/index.qmd, docs/portfolio.css, scripts/render-docs.sh 추가

이 단계의 의미는 포트폴리오가 로컬 문서 묶음에서 공개 가능한 웹 문서로 전환되었다는 점입니다.

1.6 4. 서버 런타임은 실제 앱과 운영 경로로 확장됐다

2026-04-25 b14ef51은 DevOps runtime site를 추가하면서 Dockerfile, CMakeLists.txt, src/main.cpp, GitHub Actions workflow를 함께 넣었습니다. 이후 5de6893에서 RuntimeGame, RuntimeProxy, RuntimeWeb 문서가 분리되었습니다.

축 근거
C++ edge/runtime site src/main.cpp, Dockerfile, CMakeLists.txt
RuntimeWeb 정적 문서/웹 서버 경로 검증
RuntimeProxy SNI와 route tree 기반 upstream 분기
RuntimeGame 게임 서버 런타임 관점의 모듈 검증

이 흐름은 “프레임워크를 만들었다”에서 끝나지 않고, 웹 서버와 프록시 같은 실제 앱 형태로 런타임을 검증하려 한 것으로 볼 수 있습니다.

1.7 5. 운영 대시보드는 별도 React/Vite 앱으로 커졌다

2026-04-26 10e7869에서 live ops dashboard가 추가되었고, 2026-04-27 2cd9acc에서 React/Vite 기반 OpsDashboard V2가 추가되었습니다.

파일 확인한 내용
ops_api/main.py Prometheus, Proxmox, Kubernetes, Argo CD, deploy pipeline 상태 API
dashboard/package.json Vite/React 대시보드 앱
dashboard/src/components/* Proxmox, Kubernetes, ArchitectureView, GlobalStatusBar
dashboard/public/icons.svg 독립 UI 앱으로 구성한 흔적

이 축은 개인 홈랩 운영 상태를 수동 명령어 캡처가 아니라 API와 UI로 관측하려 했다는 증거입니다.

1.8 6. 홈페이지 앱도 별도로 만들었다

2026-05-10 aa333ae는 Move homepage into portfolio repo 커밋입니다.

파일 역할
homepage/src/main.tsx 포트폴리오 진입점 UI
homepage/src/styles.css 홈페이지 전용 스타일
homepage/public/thumbnails/* ServerCore, runtime diagram, DevOps dashboard 썸네일
homepage/package.json Vite 기반 별도 프론트엔드 앱

이는 문서 목록만 노출하는 것이 아니라, 포트폴리오를 탐색 가능한 웹 앱 형태로 만들려는 작업입니다.

1.9 7. 6월에는 원본 중심 출판 파이프라인으로 재구성했다

2026-06-06 275c1c4는 기존 generated docs/ 산출물을 대량 정리하고, content/docs, content/diagrams, scripts/prepare-servercore-docs.js 중심으로 바꾼 커밋입니다.

파일 의미
content/docs/1.overview.md ~ 6.summary.md 문서 원본을 generated HTML이 아니라 Markdown source로 관리
content/diagrams/* 다이어그램 원본 자산을 source tree로 이동
scripts/prepare-servercore-docs.js Markdown을 Quarto QMD로 변환
scripts/render-docs.sh Quarto 렌더와 Pages 산출물 검증
scripts/build-pages-site.sh Pages 배포용 _site 구성

이 단계는 문서를 계속 고칠 수 있는 상태로 되돌린 작업입니다. generated HTML을 직접 관리하는 방식보다 원본 Markdown과 빌드 스크립트로 산출물을 재생성하는 구조가 포트폴리오 유지보수에 맞습니다.
