# CI/CD, GitOps, Kubernetes, 인프라 자동화

배포 흐름은 GitHub Actions에서 이미지를 만들고, GHCR에 올린 뒤, GitOps 저장소의 image tag를 갱신하고, Argo CD가 Kubernetes desired state로 수렴시키는 구조로 정리되어 있습니다. 인증된 GitHub 조회 기준으로 이 흐름은 공개 `portfolio` 저장소 안의 workflow뿐 아니라 비공개 `home-k8s-gitops`, `ops-dashboard`, `mintcocoa-ops` 저장소와도 연결됩니다.

이 구조의 출발점은 여러 작업 환경에서 같은 방식으로 빌드하고 배포해야 한다는 문제였습니다. 개인 Linux 서버와 Docker 서비스, 게임 서버, 개발 서버를 다루다 보면 로컬에서만 맞는 실행 방법은 금방 한계가 드러납니다. 그래서 GitHub Actions로 빌드를 고정하고, container image를 GHCR에 남기고, Helm chart와 GitOps repo로 배포 상태를 관리하는 방향으로 정리했습니다.

외부 접근 경로도 같은 흐름 안에 있습니다. 개발 서버를 외부에서 안전하게 열기 위해 Tailscale VPN을 사용하고, 개인 도메인은 Cloudflare DNS로 관리하며, Oracle Cloud VM은 홈 네트워크 앞단의 안전한 proxy/load balancing 경계로 둘 수 있습니다. 포트폴리오 문서에서는 이 운영 배경을 공개 가능한 GitOps, route tree, RuntimeProxy, 대시보드 증거로 설명합니다.

## 현재 workflow 근거

`.github/workflows/portfolio-image.yml`에서 확인할 수 있는 흐름입니다.

| 단계 | 파일 근거 |
| --- | --- |
| GHCR 로그인 | `docker/login-action@v3` |
| 컨테이너 이미지 빌드와 push | `docker/build-push-action@v6`, `ghcr.io/mint-cocoa/portfolio:${{ github.sha }}` |
| GitOps 저장소 checkout | `mint-cocoa/home-k8s-gitops` |
| Helm values 또는 manifest 갱신 | GitOps repo 내부에서 image tag 변경 |
| 배포 commit 생성 | `git commit -m "deploy portfolio ${GITHUB_SHA}"` |
| Pages 산출물 배포 | `actions/deploy-pages@v4` |

## GitHub 저장소 경계

운영 관련 근거는 공개 포트폴리오 저장소와 비공개 운영 저장소에 나뉘어 있습니다.

| 저장소 | 공개 여부 | 역할 |
| --- | --- | --- |
| `mint-cocoa/portfolio` | public | 문서, Pages/Quarto 출판, 공개 가능한 workflow와 대시보드 산출물 |
| `mint-cocoa/home-k8s-gitops` | private | 홈랩 Kubernetes desired state와 image tag 갱신 대상 |
| `mint-cocoa/ops-dashboard` | private | React/FastAPI 기반 운영 대시보드 원본 |
| `mint-cocoa/mintcocoa-ops` | private | cloud/home operations를 위한 GitOps와 IaC 저장소 |

따라서 이 장에서 말하는 GitOps/운영 자동화는 공개 저장소 하나만으로 완전히 재현되는 구조가 아닙니다. 공개 문서에는 민감한 kubeconfig, secret, cluster endpoint를 싣지 않고, 대신 workflow, scaffold, API shape, 대시보드 화면, 배포 단계의 흔적을 증거로 남깁니다.

## 과거 scaffold 근거

`818587c`에는 현재는 정리된 다음 파일들이 있었습니다.

| 파일 | 의미 |
| --- | --- |
| `terraform/README.md` | S3-compatible remote state, encryption, lockfile 기반 Terraform backend 계약 |
| `ansible/README.md` | Kubespray checkout과 cluster.yml 실행 절차 |
| `ansible/kubespray.lock` | Kubespray upstream ref 고정 |
| `ansible/inventory/home/hosts.yaml` | 홈랩 Kubernetes inventory |
| `gitops/secrets/README.md` | SOPS/age 기반 GitOps secret 관리 convention |
| `deploy/nfs-pv-backup-cronjob.yaml` | NFS-backed PV root를 restic으로 백업하는 CronJob |

이후 `18cf965`에서 Terraform/Ansible/GitOps scaffold 일부가 제거되었습니다. 따라서 이 부분은 “현재 운영 중인 모든 코드가 공개 `portfolio` 저장소에 남아 있다”가 아니라 “재현 가능한 인프라 자동화 단위로 정리했고, 이후 공개 포트폴리오 저장소에서는 민감하거나 불필요한 scaffold를 정리했으며, 운영 세부는 별도 private GitOps/IaC 저장소로 분리했다”라고 설명하는 편이 정확합니다.

## 운영 구성의 기본 전제

| 구성 요소 | 역할 |
| --- | --- |
| Proxmox | 홈랩 VM과 서비스 실행 기반 |
| NAS/OpenMediaVault 계열 서비스 | 파일 관리, persistent storage, 백업 경로 |
| Docker | 빠르게 여러 웹 서비스와 개발 서버를 띄우는 실행 단위 |
| Tailscale VPN | 외부에서 개발 서버와 내부 서비스에 안전하게 접근하는 경로 |
| Cloudflare DNS | 개인 도메인과 public entrypoint 관리 |
| Oracle Cloud VM | 홈 네트워크 앞단의 proxy/load balancing 또는 우회 경로 |
| GitHub Actions | 빌드와 배포 결과의 환경 차이를 줄이는 CI 경계 |
| Terraform / Helm / GitOps repo | 인프라와 앱 배포 상태를 일관된 코드 저장소로 관리 |
