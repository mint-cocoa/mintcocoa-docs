# 홈랩 운영 대시보드와 관측 가능한 증거

실제 운영 환경을 설명하려면 “구축했다”보다 “어떤 상태를 읽고, 어떤 지표로 검증했는가”가 중요합니다. 이 문서의 운영 대시보드는 이전부터 Linux 서버, Docker 서비스, 게임 서버, NAS, VPN, DNS, proxy를 직접 다루던 흐름을 관측 가능한 형태로 정리한 것입니다.

개인 서버에서는 서비스가 단일 프로세스만으로 끝나지 않습니다. Proxmox 위 VM, NAS 스토리지, Docker 또는 Kubernetes workload, 외부 접근용 VPN, 개인 도메인과 Cloudflare DNS, proxy/ingress 경로가 함께 얽힙니다. 따라서 프레임워크를 실제 앱으로 검증하려면 런타임 내부뿐 아니라 그 앱이 올라가는 운영 경로도 함께 봐야 했습니다.

## 운영 배경과 연결

| 운영 배경 | 대시보드에서 확인하려는 것 |
| --- | --- |
| Proxmox 위 VM과 NAS 서비스를 함께 사용 | VM inventory, storage path, management plane 상태 |
| Docker/Kubernetes에 여러 서비스를 올림 | workload, ingress, deployment, rollout 상태 |
| 외부에서 개발 서버와 게임 서버에 접근 | route, SNI host, tunnel/proxy 경로 |
| 개인 도메인과 Cloudflare DNS를 사용 | public entrypoint와 내부 upstream의 연결 |
| 장애 시 우회 경로나 안정적인 프록싱이 필요 | proxy destination, upstream health, deploy pipeline |
